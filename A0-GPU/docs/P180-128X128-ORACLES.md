# P180: 128×128 parameter-bound full-frame RTL oracles

P178 established pixel-accurate host versus independent P102 reference results at 64×32, 32×64 and 64×64. P180 adds an **independent** large-frame workflow and fixes two real scaled-RTL boundary defects for **128×64, 64×128 and 128×128**, exercising the current scaled core's specified 128-coordinate dimension ceiling. Existing physical and simulation acceptance thresholds remain in force. The corrected scaled RTL is reverified by them.

## Strict evidence contract

- Compile the real `a0_p172_scaled_programmed_fragment_p102_tb.sv` and corrected synthesizable design with Icarus for each geometry. Execute each shape under a finite **240-second** timeout; no skipped or downgraded tests.
- Require exactly one `P172_SCALED_PROGRAMMED_P102_PASS` and one `P173_DRAW_TIMING_PASS` marker per shape; verify clears=3, draws=2, 256 texture writes, ≥8 rejected host requests, one busy denial and one missing texture fault. Observe **5*W*H** exact reference framebuffer reads and **2*W*H** covered fragments per shape.
- New P180 total: **163,840** framebuffer observations and **65,536** shaded fragments over three shapes. The 128×128 geometry alone requires **81,920** independent framebuffer reads and **32,768** shaded fragments.
- Assert measured first/second shader completion times under the original P174 budgets `52*N+2 / 35*N+2` and accelerated P175 budgets `51*N+2 / 34*N+2`. Both transposed 128×64 and 64×128 shapes must produce equal measured times, strictly below 128×128 times.
- The R0 shader interface holds signed **Q8.8** texel coordinates. Keep successful 128-high test offsets representable; additionally run a separate deliberately overflowing offset at high Y, which **must fail closed** before any wrapped negative texture sample is accepted. Check exactly one overflow rejection marker on H=128 shapes.
- Expose 32-bit shader, texture and shaded-pixel retirement counters to avoid wrapping when 128×128 executes 81,920 shader instructions in the first pass. The host must read the full counters, not truncated 16-bit totals.
- Upload full compile and RTL simulation logs even on failure. Any timeout, comparison mismatch, unexpected geometry, missing marker, invalid cycle count or artifact failure blocks merge.

## Interpretation and safeguards

128×128 uses the existing core's highest allowed frame **dimension**, not proof of larger physical FPGA fit. P177 previously proved actual 32×32 ECP5 physical route (35.04 MHz, 77 pins, five BRAM, 72 DSP); P179 separately evaluates a 32×64 physical route. P180 must retain those physical and prior P172/P173/P178 simulation gates; its two targeted RTL bug fixes require their exact-head revalidation. The RTL test is **not** display timing, VRAM throughput, PCIe operation, game FPS or RTX 6090-class GPU readiness.

## Recorded failure and targeted correction

The first P180 head `f56688e` passed full 128×64 oracle and draw-cycle checks, but failed the 64×128 comparison at **(0,113)**: it returned RGB `67050b` where the independent shader model required `ee051c` (depth still `000040`). The 16-bit signed Q8.8 R0 coordinate wraps when `113*256+3904=32832` exceeds +32767. The correction explicitly detects pre-narrowing overflow and faults instead of sampling from a negative coordinate, then verifies full 128-high frames with a representable offset. A separate negative case asserts fault-on-overflow.

At 128×128, the first five-instruction shader would retire **81,920** instructions, beyond 16-bit telemetry. The corrected 32-bit counters preserve exact host measurements. Both changes must pass new exact-head CI, including unchanged legacy 4×4 and existing physical-route gates; historical failing evidence must remain visible.
