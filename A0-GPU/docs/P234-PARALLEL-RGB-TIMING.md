# P234 — Two externally clocked parallel RGB888 standard timing modes

## What is implemented

This is a **separate, synthesizable FPGA display bring-up top**, not an extension of the P233's 8/1024-pixel committed EBR framebuffer. The current framebuffer cannot store a genuine 640x480 or 800x600 color frame. P234 intentionally generates self-contained RGB888 eight-color bars, exact DE/HS/VS timing and a static pixel dot-clock requirement. No hidden VRAM or simulated large textures.

The board must supply the actual `pixel_clk` input and qualified `clock_locked` signal. There is **no PLL, clock generator, pixel clock physical output, VGA analog DAC, HDMI/DisplayPort PHY, link serializer, monitor EDID, hotplug, dynamic resolution changing or physical pin/electrical assignment**. The 24-bit RGB888+HS+VS+DE data bus can be reviewed for future parallel RGB test hardware only.

## Two recognized timing profiles

| MODE | Active | Dot clock input | H total: active/front/sync/back | V total: active/front/sync/back | Sync polarity | Expected frame rate |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 640×480 | 25.175 MHz | 800: 640/16/96/48 | 525: 480/10/2/33 | H− V− | ~59.9405 Hz |
| 1 | 800×600 | 40.000 MHz | 1056: 800/40/128/88 | 628: 600/1/4/23 | H+ V+ | ~60.3165 Hz |

Timing references: VESA-style DMT mode tables (e.g. Linux `Documentation/fb/viafb.modes` and published display-controller timing tables). Frequencies are *required external clock input values*, not clocks generated by this RTL. Each MODE is a compile-time parameter so it **cannot** be changed mid-frame or misrepresented as EDID-based automatic choice. MODE 2 or other modes trigger a real RTL `$fatal`.

## Behavior and tests

- On raw reset or lock loss, even while the input pixel clock is stopped, RGB=0, DE=0, HS/VS in their profile-specific inactive level. The actual counters and qualification pipeline also asynchronously clear.
- On lock recovery, do not release display signals until two valid input pixel clock edges; start at coordinate (0,0), never halfway through a frame.
- Check **every output clock edge of three complete frames** for each profile: RGB888 eight bars, black porch, DE count, exact HS/VS polarity and widths and frame wrap; each profile must contain the precise nonvacuous sample totals.
- Exercise stopping an active white pixel, lock loss without a clock edge, stalled-clock lock recovery, short 2 ns raw reset while stopped and fresh complete frames after both recoveries.
- Compile and execute an invalid MODE, requiring a `$fatal` (a compile failure is **not** credit).
- Real Yosys and nextpnr ECP5-85K CABGA381 speed6/seed1 independently route each mode at its externally required 25.175/40 MHz pixel clock. Expect exactly 30 user-visible signal bits and no framebuffer BRAM; no IO pin constraints or physical hardware timing signoff.
- First failure always retained, zero retries/skips or softened timing gates. Keep PR draft and unmerged until exact-head CI, review and owner approval.

## Relation to P233

P233 has 24-bit color signals from *real* committed 8/1024-word physical FPGA BRAM, under independently clocked host/pixel control and a qualified CE divided by two. P234 targets full standard output frame counters but presents **a synthetic diagnostic pattern, not EBR-fed 640x480/800x600 content**. These capabilities are independent prototypes and are not yet integrated.

The next bridging work must address real large framebuffer capacity/bandwidth, safe runtime mode negotiation, actual pixel clock synthesis, board-specific pin/voltage level and full display PHY. No false claims of physical monitor operation, actual GPU/VRAM or gaming capability.
