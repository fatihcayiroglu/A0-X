# P152 — First shader-microprogram-controlled triangle color in the real dual-bank raster pipeline

**Research scope. DRAFT until exact-head end-to-end Icarus and real FPGA route PASS.**

P151 executes a real bounded UNORM8 4-lane shader microprogram but was not connected to a graphics pipeline. P152 integrates P151+P150 with the actual P146/P145 paired-edge triangle raster, P144 depth/alpha RMW and P139/P138 real mapped BRAM.

The P152 renderer accepts a triangle request only when its P151 shader is idle and framebuffer is initialized, snapshots all full signed16-bit triangle coordinates, depth, alpha and scissor settings and the shader instruction count, executes **one P151 microprogram per triangle**, waits for its exact final `shader_done` and committed vector destination register **R2**, and then launches P145 with **R2[23:0] as the actual triangle RGB input**. The draw-complete pulse is returned **only after the real raster and framebuffer RMW finish**. No speculative writes occur if shader faults. Shader configuration writes are accepted only while idle, and host framebuffer read requests are blocked during shader execution as well as raster. Clear still bypasses shader. Shared reset aborts both shader and raster and clears prior memory state.

This is an important true integration boundary, **not a per-fragment shader**. Every fragment of one triangle receives the **same program-derived RGB**; it does not independently execute for each pixel, interpolate per-vertex attributes, sample textures, fetch arbitrary VRAM, execute FP32, branches or compile OpenGL/Vulkan/DirectX shaders. P153+ needs a genuine fragment invocation/attribute pipeline.

A second real full-16bit `a0_p152_packed_shaded_command_top` adapts the previously proven P147 32bit host-bus concept to the P152 engine with **76 external logical signals** and additional shader register selection/data/instruction/length/status offsets at 16–22. The host writes full 32-bit shader vector registers using SELECT (bits[6:4]) and REG_DATA, and full 24-bit instructions using SELECT (bits[3:0]) and INSN_DATA. Invalid instruction upper bits, unsupported shader operations during busy, invalid program length, and old unshaded TRI_RGB writes fail closed; the shader result R2 actually drives draw pixels. Command 1=CLEAR, 2=DRAW, 3=READ_PIXEL; ordinary registers and clear/draw completion/status readbacks preserve the P147 contract. No PCIe, AXI, external pin assignments, driver or DMA is implemented.

## Exact acceptance criteria

- Real Icarus on 4×4, 7×5, 8×8, each with two clears, five successfully completed triangles, full RGB/depth readback of all pixels after each operation against original **unchanged independent P102** with shader colors independently evaluated using scalar integer `/255` math, alpha blend/depth/scissor/degenerate/reset mid-flight. Verify 1- and 2-instruction shader programs and nonzero double pixel commits, exact completed triangle writes and no host reads during active work.
- A **separate** bus-level Icarus oracle must drive the actual P152 packed host protocol, program shader registers/instructions, send wide signed16-bit triangles (e.g. −257 and +1024), verify R2 RGB and retired counts through the bus and match all post-clear/draw framebuffer RGB and depth against P102. No opaque direct connections to candidate shader/raster except the test's reference launch strobe to synchronize the two independently scheduled architectures.
- Full genuine Yosys `synth_ecp5` and nextpnr ECP5-85K, CABGA756 speed6 seed1, 4×4, `--freq 5 --lpf-allow-unconstrained` including **P150+P151+P152 shader and the full P145+P144+P139+P138 raster/BRAM**. Require exactly **76 external logical I/O bits**, at least two real `DP16KD` BRAM and four real `MULT18X18D` DSP multipliers, no unmapped cells/latches, a usable routed clock report and physical I/O utilization below package capacity. Report true utilization/Fmax rather than pretending P151's isolated 33.59MHz and P149's 21.41MHz are equivalent.
- Required exact PR head inherited P126/P127 and P152 CI all SUCCESS before non-draft or merge.

No physical GPU card, PCIe endpoint, external VRAM, software shader compiler, FPS result or RTX 6090 competitiveness is established by this phase.
